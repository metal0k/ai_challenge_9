# Команды

У репозитория несколько точек входа.

- `advent` — чат и замеры недели 01, а также `record` и `submit`.
- `adventagent` — агент с сессией, памятью и контекстом.
- `adventmcp` — клиент MCP.
- `adventrag` — индекс и поиск RAG.
- `adventlocal` — локальная модель и сравнение с облаком.
- `adventassistant` — вопросы о проекте.

Команда `/help` ассистента читает этот корпус и текущую ветку.

`adventassistant help` отвечает одним запросом. Вопрос о ветке и вопрос об
изменениях берут текст из git. Остальные вопросы отвечаются по фрагментам
этого корпуса; если опоры нет, ответ — строка `не знаю`.

`adventassistant index-review` строит отдельный индекс для ревью кода.
`adventassistant review` разбирает диапазон `base...head`.

`adventassistant watch-pr` — локальный watcher открытых PR. По умолчанию
проверяет репозиторий раз в 60 секунд и публикует ревью в комментарии.
Новая ревизия базы или головы запускает новое ревью; повторная проверка
обработанной ревизии пропускает модель и комментарий. Остановка — Ctrl+C.

- `watch-pr --once` — один проход, удобно для внешнего планировщика.
- `watch-pr --pr 123 --once` — проверить только выбранный PR.
- `watch-pr --no-post` — сохранять отчёт локально и печатать его без комментария.
- `watch-pr --interval 30` — изменить период проверки, минимум 5 секунд.
- `--state` и `--cache-dir` — отдельные пути для состояния и кэша индексов.

Для watcher нужны `GITHUB_URL`, `GITHUB_TOKEN` и `MISTRAL_API_KEY` в `.env`.
Токену нужен доступ к репозиторию и комментариям PR; GitHub Actions Secrets
и право Workflows не используются. GitHub CLI тоже не требуется.
Оркестрация выполняется локально, модель и embeddings — через Mistral API.
Состояние и отчёты сохраняются в `data/review/`; ошибка отправки комментария
не приводит к повторной оплате уже готового ревью.

Если в окружении задан SOCKS `ALL_PROXY`, перед запуском на Windows:
`$env:ALL_PROXY = ''; uv run adventassistant watch-pr`.
Настройка `HTTPS_PROXY` при этом сохраняется.

Токен не помещается в URL, который передаётся git.
Для HTTPS-аутентификации токен передаётся только в разовом заголовке:
`git -c credential.helper= -c http.extraheader="Authorization: Basic <base64>" push origin <ref>`.
`<base64>` — кодировка пары логин:токен, а не значение, записанное в репозитории.
Процесс запускается с `GIT_TERMINAL_PROMPT=0` и `GCM_INTERACTIVE=Never`;
при отказе авторизации работа останавливается. Параметра `git --header` нет.
