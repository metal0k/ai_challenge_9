# Неделя 02

Код недели лежит в этой папке; условия дней — разделы `## Day NN` в
[`tasks_02.md`](tasks_02.md) рядом.

## Day 06 — первый агент

**Условие:** [`tasks_02.md`](tasks_02.md#day-06) — агент принимает запрос,
отправляет его в LLM через API, получает ответ и выводит результат. Важно:
агент — отдельная сущность, а не один вызов API.

### Что сделано

Агент — это `advent_core/agent.py` (сборка запроса, обрезка контекста, детект
завершения), `advent_core/session.py` (именованная память на диске) и
`advent_core/tokens.py` (счёт токенов до отправки). В `week_02/` остались
интерфейс и промпты недели.

- **Отдельная команда `adventagent`**, не подкоманда `advent w02`: неделя 03
  продолжает того же агента. Позиционного вопроса нет сознательно — агент
  настраивается и запускается как разговор.
- **Память между запусками**: `logs/sessions/<имя>.json`, запись атомарная,
  битый файл — предупреждение и пустая сессия, а не падение.
- **Учёт токенов**: точный токенизатор Mistral (tekken) там, где он известен,
  калиброванная оценка (`~`) для остальных моделей. Неизвестное печатается как
  `—` и никогда как `0`.
- **Заполненность контекста** показывается для *следующего* запроса, до
  отправки; при переполнении старые ходы выбрасываются парами, вслух.
- **Два режима**: `chat` и `dialog` (агент сам задаёт по одному уточняющему
  вопросу до маркера завершения или потолка ходов). Диалог идёт в общей памяти
  сессии, а не отдельной.
- **Состояние диалога переживает перезапуск**: режим (`mode`), маркер `done` и
  счётчик ходов пишутся в файл сессии и подхватываются при старте — «как будто
  не выключался» верно и для целевого диалога. Явный флаг `--mode`/`--done`
  бьёт файл сессии.
- **Смена модели внутри сессии** — предупреждение, а не молчаливая подмена:
  модель хранится на каждый ход.
- Слэш-команды собраны в реестр (декоратор + алиасы), а не в цепочку `if/elif`.
- **Голые `/model` и `/set` в терминале открывают интерактивный выбор**
  (только при tty): запись демо и скрипты гоняют REPL через pipe — там обе
  команды ведут себя по-старому.

### Как запустить

```bash
uv run adventagent                          # разговор в сессии default
uv run adventagent --session recipes        # своя память под свою тему
uv run adventagent --model ministral-3b-latest --no-stream
uv run adventagent --mode dialog            # целевой диалог с первого хода
uv run adventagent --verbose                # детали запуска в stderr
```

Флаги: `--session`, `--model`, `--system`, `--base-url`, `--mode`, `--done`,
`--max-turns`, `--context-limit`, параметры генерации (`--temperature`, `--top-p`, `--max-tokens`,
`--seed`, `--stop`, `--reasoning-effort`, `--format`, `--schema-file`),
`--stream/--no-stream`, `--verbose`. Умолчания приходят из реестра параметров,
их печатает `--help` и `/params`.

Первый запуск на модели с точным токенизатором скачивает `tekken.json`
(~17 МБ) в `logs/cache/tokenizers/` — один раз, дальше из кэша. Если
скачивание не удалось, агент работает и считает оценкой, пометив её `~`.

### Команды разговора

| Команда | Что делает |
|---------|-----------|
| `/help` | список команд |
| `/model [<имя>\|list [all]\|info]` | текущая модель; без аргументов — интерактивный выбор; переключение, таблица, карточка |
| `/params` | параметры, которые агент читает, и итоговый system prompt |
| `/set <параметр> <значение>` | изменить параметр; без аргументов — интерактивный выбор (`default` — вернуть умолчание) |
| `/mode [chat\|dialog]` | режим разговора |
| `/again` | повторить последний вопрос без истории (в память сессии не пишется) |
| `/reset` | очистить рабочий контекст запуска (файл сессии остаётся) |
| `/new [<имя>]` | начать пустую сессию (содержимое стирается) |
| `/sessions` | список сессий: дата, ходы, токены |
| `/tokens` | разбивка: сессия, окно контекста, сверка счёта с сервером, таблица роста по ходам |
| `/compact` | сжать историю прямо сейчас, не дожидаясь порога (день 09) |
| `/summary` | текущий пересказ и сколько сообщений он покрывает (день 09) |
| `/facts [backfill]` | показать блок facts целиком; `backfill` — пересобрать одним вызовом по всей сессии (день 10) |
| `/fact set\|del\|unpin <ключ> [значение]` | ручная правка facts; `set` закрепляет ключ (день 10) |
| `/checkpoint [имя]` | снимок сессии целиком; без имени — список checkpoint'ов (день 10) |
| `/branch <имя> [--from <checkpoint>] \| --delete <имя>` | ответвиться в новую сессию / удалить ветку (день 10) |
| `/switch <имя>` | перейти в сессию или ветку (день 10) |
| `/branches` | дерево веток и checkpoint'ов текущего корня (день 10) |
| `/exit` | выход |

Многострочный ввод — тройная кавычка `"""` на отдельной строке: открывает и
закрывает блок. Shift+Enter не используется — портируемого способа поймать его
в терминалах нет.

Ответ модели идёт в **stdout**, всё остальное (панель токенов, footer,
предупреждения, приглашение, список сессий) — в **stderr**.

### Запись демо

```bash
uv run advent record --week 2 --day 6 --dry-run   # прогон без записи
uv run advent record --week 2 --day 6             # запись через OBS
uv run advent submit --week 2 --day 6             # ссылки для сдачи
```

Сценарий записи (`advent_cli/record.py`) работает в сессиях `demo` и `recipes`
и начинается с `/new` — рабочая память (`default`) при записи не страдает.

## Day 07 — сохранение контекста

**Условие:** [`tasks_02.md`](tasks_02.md#day-07) — хранить историю диалога в
JSON или SQLite, при перезапуске загружать обратно и продолжать «как будто
агент не выключался». Проверка прописана в задании: начать диалог,
перезапустить, убедиться, что агент помнит.

### Что сделано

Базовое требование закрыла уже память дня 06 (выше): день 07 — проверка
непрерывности на перезапуске плюс закрытие найденной дырки — **служебного
состояния запуска**. Выход посреди целевого диалога терял режим, маркер
завершения и счётчик ходов: после перезапуска агент помнил разговор, но не
помнил, что в нём делал.

- `state` — аддитивный ключ файла сессии (без bump версии: тегированный код
  дня 06 читает новые файлы, и наоборот): режим, маркер `done`, счётчик ходов.
- Приоритет: явный флаг > файл сессии > дефолт реестра.
- Запись state при каждом его изменении, а не только после хода.
- Голые `/model` и `/set` — интерактивный выбор, только при tty.

Демо: сессия `demo`, шаги — отдельные процессы (перезапуск честный),
файл сессии показывается глазами через `python -m json.tool`.

## Day 08 — работа с токенами

**Условие:** [`tasks_02.md`](tasks_02.md#day-08) — подсчёт токенов для текущего
запроса, всей истории и ответа модели; сравнение короткого, длинного и
превышающего лимит диалогов; показать, как растут токены по мере диалога и что
ломается при переполнении.

### Что сделано

Базовый подсчёт — день 06 (контекст до отправки, usage по ответу, футер,
trim). День 08 добавляет то, чего не хватало до формулировки задания:

- **`/tokens`: таблица роста по ходам** — вторая таблица команды:
  prompt/completion/накопительно из `usage` ходов сессии (факт сервера, не
  оценка). Ход без usage — прочерки. При больше 30 ходах — последние 30 со
  строкой «… показаны последние 30 из N». Именно накопительная колонка
  показывает, как «стоимость диалога в токенах» растёт квадратично его длине:
  история пересылается целиком.
- **`context_limit` — override окна** (поведенческий параметр, в payload API
  не уходит). `/set context_limit 2500` занижает окно, `/set context_limit
  default` возвращает карточку модели. Приоритет: явный флаг > state сессии >
  карточка; override пишется в state и переживает перезапуск. Видимость
  обязательна: note при старте, метка `(override)` в футере, оба числа в
  `/tokens`, предупреждение при `/model`. С override trim работает по
  заниженному бюджету — переполнение видно на десятке ходов: `dropped_tokens`
  и футер говорят, что именно выброшено.
- **Серверное переполнение — гигантский ввод**: одно сообщение длиннее окна
  (`ministral-14b` — 262144) уходит как есть, сервер отвечает честным HTTP 400
  (`invalid_request_prompt_too_long`), и `errors.py` печатает хинт с обоими
  числами («прислано N, лимит M») и советом `/new`. Сессия живёт, ход в
  историю не пишется. Генератор ввода — `tools/make_biginput.py`: одна строка
  из нумерованных разнообразных фраз (BPE сжимает монотонные повторы) на окно
  + margin, размер считается точным токенизатором tekken.
- **Оценка ответа без usage**: когда сервер не прислал `completion_tokens`
  (стрим LM Studio), футер считает ответ локально и показывает `~N` — с
  тильдой, как всякая оценка; счётчика нет — «?». Неизвестное никогда не
  становится нулём.

### Как запустить

```bash
uv run adventagent                         # лимит окна — из карточки модели
uv run adventagent --context-limit 2500    # override на старте
```

В разговоре: `/set context_limit 2500`, `/set context_limit default`, `/tokens`
— сводка, сверка с сервером и таблица роста.

### Запись демо

```bash
uv run advent record --week 2 --day 8 --dry-run   # прогон без записи
uv run advent record --week 2 --day 8             # запись через OBS
uv run advent submit --week 2 --day 8             # ссылки для сдачи
```

Сценарий (`_demo_steps_w02d08`) работает в сессии `demo08` и начинается с
`/new`: короткий диалог + `/tokens`, длинный диалог из восьми вопросов +
`/tokens`, `/set context_limit 2500` с кодовым словом и «забыванием» под
trim, и в финале генератор гигантского ввода плюс реальный 400 с хинтом.

## Day 09 — сжатие истории

**Условие:** [`tasks_02.md`](tasks_02.md#day-09) — оставлять последние N
сообщений как есть, остальное заменять кратким пересказом; хранить пересказ
отдельно и подставлять в запрос вместо полной истории; сравнить качество
ответов и расход токенов до и после.

### Что сделано

День 08 показал, что при переполнении окна trim просто **выбрасывает** начало
разговора — вместе с фактами, которые в нём были. День 09 добавляет второй
исход: старые сообщения не пропадают, а сворачиваются в пересказ.

- **`advent_core/compact.py`** — чистые функции без сети и без состояния:
  `split_history` (граница «хвост как есть» / «остальное в пересказ»; хвост
  всегда начинается с реплики пользователя), `should_compact` (правило
  запуска), `fold_summary` (новый пересказ вбирает предыдущий),
  `summary_messages` (форма подстановки).
- **Пересказ подставляется псевдо-парой в голову истории** — сообщение
  пользователя с текстом пересказа и короткий ответ ассистента. Не в system
  prompt: персона постоянна, а пересказ переписывается каждые несколько ходов,
  и смешивать их — значит потерять и то и другое.
- **Два триггера, одна функция:** по бюджету окна (запрос перестал влезать) и
  по счётчику несжатых старых сообщений (`compact_every`). Trim остаётся
  последним рубежом и **никогда не выбрасывает саму псевдо-пару** — она и есть
  сжатая форма всего, что уже выброшено.
- **Сжатие стоит денег, и это видно.** Вызов суммаризатора не попадает в
  историю сессии, но пишется в журнал с пометкой `kind="compact"`, называется
  нотой в момент срабатывания и отдельной строкой в `/tokens` — сколько сжатий
  и во сколько токенов они обошлись.
- **Пересказ переживает перезапуск**: ключи `summary` и `summary_upto` в state
  сессии (аддитивно, без bump версии файла). `/new` пересказ стирает —
  это содержимое разговора, а не настройка.
- **Параметры:** `compact` (по умолчанию **on**), `keep_last` (6),
  `compact_every` (10). Ни один не уходит в payload API — это поведение
  агента, а не генерации.
- **Оффлайн-сравнение — `tools/compact_bench.py`**: один и тот же сценарий
  прогоняется дважды, `compact off` против `compact on`, при заниженном окне.
  Таблица печатает prompt-токены по ходам и накопительно, число сжатий и их
  цену, чистую экономию (`off − on − цена сжатий`) и то, вспомнил ли агент
  подложенное в начало разговора кодовое слово. Качество меряется фактом, а
  не LLM-судьёй: ground truth здесь проверяется точно и бесплатно.

### Что показал живой замер

Три прогона 2026-09-10, один и тот же сценарий из 12 ходов,
`ministral-14b-latest`, каждый прогон дважды (off/on):

| окно | keep_last / compact_every | сжатий | чистая экономия | кодовое слово |
|---|---|---|---|---|
| 2500 | 6 / 10 | 2 | **−3464** | помнит только сжатие |
| 8000 | 6 / 10 | 1 | **−867** | помнят оба |
| 8000 | 4 / 4 | 4 | **−4163** | помнят оба |

**Вывод дня обратный ожидаемому: на коротком разговоре сжатие не экономит
токены, а покупает на них память.** Одно сжатие стоит ~1450 токенов
(суммаризатор читает всю старую историю целиком) и экономит 150–460
prompt-токенов на каждом *последующем* ходе — двенадцати ходов на возврат не
хватает, а сжимать чаще строго хуже. При окне 2500 обе ветки вообще стоят
одинаково (10896 против 10918): trim режет запрос до того же бюджета, и вся
разница в том, что кодовое слово пережило только сжатие. Поэтому харнесс
печатает вердикт словами рядом с числом — голое отрицательное число читается
как «фича не сработала», хотя сработала, просто платит за другое.

### Как запустить

```bash
uv run adventagent                                   # сжатие включено по умолчанию
uv run python tools/compact_bench.py --limit 2500    # сравнение off/on в цифрах
uv run python tools/compact_bench.py --dry-run       # сценарий сравнения, без сети

# короткий прогон (тот, что идёт в кадре): шесть ходов вместо двенадцати
uv run python tools/compact_bench.py --limit 1700 --turns 6 --keep-last 2 --compact-every 2
```

`--turns N` берёт первые N−1 ходов сценария и всегда добавляет последним вопрос
про кодовое слово — иначе укороченный прогон сравнивал бы две ветки, ни разу не
проверив, что агент помнит. Окно и пороги при этом приходится опускать вместе с
длиной: при `keep_last 6` и шести ходах trim держит историю ровно в хвосте,
`older` остаётся пуст, и сжатие не срабатывает ни разу.

В разговоре: `/set compact off` — вернуть поведение дня 08, `/compact` — сжать
прямо сейчас, `/summary` — посмотреть, что агент помнит вместо выброшенного,
`/tokens` — строка про сжатия и их цену.

### Запись демо

```bash
uv run advent record --week 2 --day 9 --dry-run   # прогон без записи
uv run advent record --week 2 --day 9             # запись через OBS
uv run advent submit --week 2 --day 9             # ссылки для сдачи
```

Сценарий (`_demo_steps_w02d09`) — три шага: живой диалог со сжатием при
заниженном окне (кодовое слово переживает trim) и `/tokens`; `/summary` +
`/tokens` отдельным процессом — пересказ пережил перезапуск; короткий прогон
`compact_bench` в финале. Живого диалога **без** сжатия в кадре нет намеренно:
ту же ветку показывает колонка `compact off` в таблице харнесса вместе со
строкой «кодовое слово вспомнено: нет», а вживую это те же двенадцать ходов
третий раз за дубль.

## Day 10 — стратегии управления контекстом

**Условие:** [`tasks_02.md`](tasks_02.md#day-10) — реализовать несколько
стратегий (Sliding Window / Sticky Facts / Branching), переключатель между
ними и прогон одного сценария на каждой; сравнить по качеству, стабильности,
расходу токенов и удобству.

**Спецификация:** [`specs/SPEC-w02d10.md`](../specs/SPEC-w02d10.md) (не в
репозитории — `specs/` в `.gitignore`); ключевые числа живого замера
экстрактора — `specs/PROBE-w02d10-facts.md`, там же.

### Что сделано

День 09 уже умел сжимать историю в пересказ. День 10 не заменяет это, а делает
пересказ **одним из четырёх значений** одного переключателя — `summary` из дня
09 остаётся дефолтом, чтобы ни один старый файл сессии, ни один тест не
поменяли смысл молча.

### `/strategy` — один параметр, четыре значения

`keep_last` (день 09, по умолчанию 6) переиспользуется как N для всех значений,
кроме `branch` — второй параметр с тем же смыслом разошёлся бы с первым на
второй же день.

| значение | что уходит в запрос | побочные вызовы |
|---|---|---|
| `window` | system + последние N сообщений | нет |
| `facts` | system + блок facts псевдо-парой + последние N | extractor, 1 на ход |
| `summary` (default) | пересказ псевдо-парой + хвост (поведение дня 09) | суммаризатор, по триггеру |
| `branch` | system + **вся** история активной ветки | нет |

`/strategy` без значения печатает текущую стратегию и список; `/strategy facts`
переключает. Это обёртка над `/set context_strategy` — разбор, проверка и
побочные эффекты переключения живут в одном месте, иначе `/strategy fcts` и
`/set context_strategy fcts` однажды ответят по-разному.

Под всеми четырьмя остаётся trim по бюджету (`context_limit` минус
резерв под ответ) — это страховка от 400, а не стратегия. Для `branch` это
единственный ограничитель — при переполнении он сам вырождается в `window`.
Цена `branch` при этом не гарантированно самая высокая: измерена дважды как
самая **низкая** из четырёх, потому что накопительный prompt зависит и от
длины ответов модели, а не только от объёма отправляемой истории.

`/set compact off|on` (день 09) остаётся рабочим алиасом: `off` → `window`,
`on` → `summary`, с нотой об этом. Явно заданный `context_strategy` в текущем
запуске сильнее — `compact` тогда только говорит, что он ничего не решает.

### Sticky Facts (`advent_core/facts.py`)

Отдельный, **платный** вызов на каждый ход — второй LLM-запрос, а не эвристика:
экстрактор читает текущий блок facts, предыдущий ответ ассистента и новое
сообщение, возвращает дельту `{"set": [...], "delete": [...]}` через
`format="schema"`, и после успешного вызова курсор `facts_upto` сдвигается.
Сбой (429, невалидная схема) не роняет ход — ответ идёт со старыми facts,
предупреждением, и следующий успешный вызов догоняет всё непокрытое (до
`FACTS_CATCHUP_MAX` сообщений, дальше — обрезка с предупреждением вслух).

- **`/facts`** — показать блок целиком (закреплённые ключи помечены `📌`);
  **`/facts backfill`** — пересобрать одним вызовом по всей сессии (нужно при
  переключении на `facts` из пустого блока — иначе агент выглядит внезапно
  забывшим то, что сам же обсуждал).
- **`/fact set <категория.имя> <значение>`** — записать и **закрепить**:
  закреплённый ключ экстрактор не трогает, его правки над ним отбрасываются
  (`facts: … — правка пользователя сохранена`). Без этого правка жила бы один
  ход — экстрактор «исправил» бы её обратно по тексту диалога на следующем.
- **`/fact del <ключ>`** / **`/fact unpin <ключ>`** — удалить (в том числе
  закреплённое — это явное действие) / снять закрепление.
- Категории фиксированы (`цель`, `ограничения`, `предпочтения`, `решения`,
  `договорённости`), ключ — `категория.имя`; порядок в блоке стабилен между
  вызовами, чтобы токены блока были сравнимы от хода к ходу.

**Что показал probe (`specs/PROBE-w02d10-facts.md`, 12 ходов, `ministral-14b-latest`,
2026-09-12): экстрактор стоит ~850 токенов на ход (805 prompt + 45 completion,
медианы) — на 12-ходовом разговоре это около 10 тысяч токенов сверх самого
диалога, при том что сам блок facts весит всего 193 токена к 12-му ходу.
Дорога не память, а её пересборка. Прямое следствие: `facts` почти наверняка
дороже `window` и, возможно, дороже `summary` — facts покупают стабильность
детали ценой токенов, а не экономят их**, ровно как день 09 выяснил про
`summary` («сжатие не экономит токены — оно меняет их на память»).

### Branching

Ветка — не стратегия сборки запроса, а операция над сессией, ортогональная
всем четырём значениям `context_strategy`.

- **`/checkpoint [имя]`** — немедленный снимок сессии **целиком** (ходы,
  facts, summary, `mode`, `context_strategy`, `context_limit`) в отдельный
  файл `<сессия>--cp-<имя>`; без имени печатает список checkpoint'ов текущей
  сессии. В checkpoint нельзя `/switch` — только ответвиться от него.
- **`/branch <имя> [--from <checkpoint>] | --delete <имя>`** — ответвиться в
  новую сессию `<родитель>--<имя>` (снимком checkpoint'а) и переключиться в
  неё; `--from` обязателен, если checkpoint'ов больше одного. Ветвление от
  ветки разрешено (`demo10--mvp--lite`). `/new` внутри ветки чистит только её
  файл, родителя не трогает никогда; удалить текущую ветку нельзя.
- **`/switch <имя>`** — перейти в сессию или ветку; если `context_strategy`,
  `context_limit` или `mode` цели отличаются от текущих, печатается нота с
  разницей (молчаливая смена стратегии читалась бы как поломка агента).
- **`/branches`** — дерево веток и checkpoint'ов текущего корня.

### `tools/strategy_bench.py` — офлайн-сравнение четырёх стратегий

```bash
uv run python -m tools.strategy_bench                       # полный прогон, все четыре стратегии
uv run python -m tools.strategy_bench --dry-run              # сценарий и чеклист, без сети
uv run python -m tools.strategy_bench --strategies window,facts
uv run python -m tools.strategy_bench --turns 8 --limit 4000 --keep-last 3 \n    --strategies window,facts --no-fork                      # короткий прогон (кадр)
```

Флаги: `--model` (по умолчанию `ministral-14b-latest`), `--limit` (узкое окно
`context_limit`, по умолчанию 4000), `--turns` (по умолчанию все 12, не меньше
8 — иначе плантированным деталям негде поместиться), `--keep-last`,
`--strategies window,facts,summary,branch` (список через запятую),
`--fork/--no-fork` (секция изоляции веток, по умолчанию включена), `--dry-run`.

Один и тот же 12-ходовый сценарий (ТЗ на мобильное приложение для кофейни, с
шестью плантированными деталями и одной переигранной — бюджет 480 → 520)
прогоняется под каждой стратегией; таблица печатает детали (n/6), вернулось ли
старое значение, prompt накопительно, цену побочных вызовов, сколько из них
оплачено впустую (`facts_failed` — билось, но не дало ничего использовать), и
итог, плюс вердикт словами (facts дороже — это ожидаемо, не поломка; `branch` —
lossless-базлайн по контексту, а не гарантия ни числа деталей в финальном
ответе, ни первого места по цене — оба живой замер 2026-09-12 показал
вариативными от прогона к прогону). Отдельная секция проверяет
изоляцию веток: checkpoint после хода 6, две ветки с противоречащим бюджетом
(520 против 300), вопрос про бюджет в каждой — печатается, вытекли ли facts.

**Качество ответа и удобство — это данные, не число от судьи.** Таблица
проверяет детали подстрокой, но не показывает сам ответ, а «удобство» число не
измеряет вовсе — оба пробела закрыты выводом, а не оценкой: после таблицы
печатается итоговый ответ («выпиши ТЗ одним списком») каждой стратегии
(обрезанный с явной пометкой длины, если длинный), а в секции изоляции —
ответ каждой ветки о своём бюджете. Судьи-LLM здесь нет по тому же правилу,
что убрало его из дня 04 («отдай оценку креативности человеку, просто выведи
данные») — оценивает качество читатель, глядя на текст.

Удобство для пользователя — по тому, что стратегия реально требует: `window` и
`summary` не просят ни одной команды и решают сами на каждом ходу; `facts`
тоже работает без команд на ходу, но правка неверного значения идёт через
`/fact set|del|unpin`, а включение с пустых facts требует явного
`/facts backfill`; `branch` — единственная стратегия, где ветвление и
переключение целиком на пользователе (`/checkpoint`, `/branch`, `/switch`,
`/branches`) — сама она никогда не разветвится и не переключится.

**Побочный вызов, который оплачен и не дал ничего, не должен пропадать из
итога.** `side_call_totals()` в `tools/bench_core.py` считал только успешные
`Compaction`/`FactsUpdate`; вызов экстрактора, упавший на невалидной дельте
(`AgentReply.facts_failed`), стоил реальных токенов и раньше не попадал в
таблицу вовсе — итог получался меньше, чем было потрачено на самом деле
(живой прогон 2026-09-12). Теперь `facts_failed` считается в общей цене
побочных вызовов, а отдельная колонка «впустую» и строка вердикта называют,
сколько из них не дали ничего использовать — «оплачено, впустую» это
результат, а не то, что тихо исчезает из таблицы.

Общий движок обоих харнессов (день 09 и день 10) — `tools/bench_core.py`:
прогон сценария через `Agent.ask()`, накопительные колонки, общий каркас
argparse с `--model/--limit/--dry-run`. `tools/compact_bench.py` переведён на
него **без изменения вывода** — 9 тестов дня 09 остаются зелёными как есть.


Сценарий (`_demo_steps_w02d10`) — три шага в сессии `demo10`: facts живьём
(узкое окно, семь ходов сценария из `tools/strategy_bench.py` — импортированы,
а не перепечатаны, — переигранная деталь, `/facts`, `/tokens`); ветвление

своим числом); короткий прогон `strategy_bench` в финале. Пороги короткого
прогона (`--turns 8 --limit 4000 --keep-last 3`) подтверждены живым прогоном
2026-09-12, а не выведены рассуждением: при `--limit 2000` safety-net резал
сам `branch` (2 хода, 6 сообщений, 416 токенов), то есть базлайн переставал
быть lossless прямо в кадре. На 4000 обрезка не срабатывает ни у `branch`, ни
у `window`, а стратегии по-прежнему расходятся наглядно: `window` помнит 2
детали из 6 за 6624 токена — дороже, чем lossless-`branch` с 6/6 за 5804, —
а `facts` берёт те же 6/6 за 21491.
