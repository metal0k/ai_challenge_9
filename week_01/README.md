# Неделя 01

Код всей недели лежит в этой папке; условия дней — файлы `task_NN.md` рядом.
Приложение растёт по дням, состояние каждого сданного дня зафиксировано тегом.

## Day 01 — первый запрос к LLM через API

**Условие:** [`task_01.md`](task_01.md) — минимальный код, который отправляет
запрос в LLM через API, получает ответ и выводит его в CLI.
**Тег:** [`w01d01`](https://github.com/metal0k/ai_challenge_9/tree/w01d01)

### Что сделано

- Запрос в Mistral через официальный SDK, **streaming** — токены печатаются по
  мере генерации.
- Два режима: one-shot (`advent w01 chat "вопрос"`) и REPL с историей диалога.
- Выбор модели и её настроек: `/model list`, `/model info`, `/params`, `/set`.
- Телеметрия после ответа: реальная версия модели, latency, токены.
- Понятные ошибки вместо traceback: нет ключа, неверный ключ, лимит, таймаут.
- Все вызовы пишутся в `logs/calls.jsonl` — пригодится в поздних заданиях.

### Команды

| Команда | Что делает |
|---------|-----------|
| `advent w01 chat [вопрос]` | Вопрос модели; без аргумента — REPL |
| `advent w01 models` | Список моделей из API (`--all` — включая не-chat) |

Флаги `chat`: `--model`, `--system`, `--temperature`, `--top-p`, `--max-tokens`,
`--seed`, `--stop`, `--reasoning-effort`, `--no-stream`, `--verbose`.

Команды REPL: `/help`, `/model`, `/model <имя>`, `/model list`, `/model info`,
`/params`, `/set <параметр> <значение>`, `/reset`, `/exit`.

### Демо-сценарий

Фиксированный: модель каждый раз отвечает по-разному, а порядок шагов — нет.
Прогоняется одной командой `uv run advent record --day 1` (или `--dry-run`,
чтобы посмотреть без записи).

**1. Какие модели доступны аккаунту**

```bash
uv run advent w01 models
```

Список приходит из живого `GET /v1/models`, а не зашит в код. Внизу видно, во
что разрешается алиас: `mistral-small-latest сейчас разрешается в mistral-small-2603`.

**2. Один вопрос — ответ стримится**

```bash
uv run advent w01 chat "Объясни в двух предложениях, что такое LLM"
```

Ответ печатается по мере генерации, в конце — футер:
`· model mistral-small-latest → mistral-small-2603 · 2480 ms · tokens 73/76/149`

**3. Диалог с историей**

- `Назови три языка программирования для бэкенда`
- `А какой из них быстрее всего учить?` — второй вопрос опирается на первый,
  модель помнит контекст
- `/reset`, `/exit`

**4. Настройки модели**

`/model info` → `/params` → `/set temperature 0` → `/set reasoning_effort high`
→ вопрос → `/model codestral-latest`. На последнем шаге видно, как параметр,
которого у модели нет, отсеивается с предупреждением.

**5. Неверный ключ — аккуратная ошибка**

```bash
MISTRAL_API_KEY=invalid uv run advent w01 chat "привет"
```

```
Ошибка: Ключ Mistral отклонён (401).
Проверь MISTRAL_API_KEY в .env — возможно, ключ отозван или скопирован не полностью.
```

Exit code 3, никакого traceback.

## Настройки модели

Список моделей, их возможности и рекомендованные настройки берутся из живого
`GET /v1/models`, а не зашиты в код. По каждой модели API отдаёт `capabilities`,
`max_context_length` и `default_model_temperature` — на этом и построены команды.

**`/model list`** — таблица chat-моделей (29 из 48 на этом аккаунте):

```
┌─────────────────────────┬──────┬─────┬──────────────────────────┬─────────┐
│ id                      │  ctx │  t° │ возможности              │ алиасы  │
├─────────────────────────┼──────┼─────┼──────────────────────────┼─────────┤
│ codestral-2508          │ 250k │ 0.3 │ tools, fim               │ …       │
│ magistral-medium-latest │ 256k │ 1.0 │ reasoning, vision, tools │ …       │
└─────────────────────────┴──────┴─────┴──────────────────────────┴─────────┘
```

`/model list all` добавляет embedding, OCR и аудио-модели.

**`/model info`** — карточка текущей:

```
запрошена        mistral-small-latest
реальная версия  mistral-small-2603
описание         Mistral Small 4.
контекст         256k
рекоменд. t°     0.3
возможности      reasoning, vision, tools
алиасы           mistral-small-latest, mistral-vibe-cli-fast, magistral-small-latest
```

Модель, снимаемая с поддержки, помечается жёлтым и печатает дату вывода вместе
с заменой — узнать об этом лучше заранее, чем по внезапной ошибке.

**`/params` и `/set`** — крутить генерацию на лету:

```
/set temperature 0
/set reasoning_effort high
/set max_tokens default      # сбросить
```

Доступны `temperature`, `top_p`, `max_tokens`, `random_seed`, `stop`,
`reasoning_effort`. Те же значения задаются флагами CLI и переменными `.env`.

## Решения, которые стоит объяснить

- **SDK `mistralai` версии 2.** Импорты переехали из `mistralai` в
  `mistralai.client`; версия запинена в `pyproject.toml`, иначе примеры из
  интернета для v1 не заработают.
- **Незаданный параметр не отправляется вообще.** Соблазн подставить
  `temperature=0.7` константой велик, но API уже знает рекомендованное для
  каждой модели значение — у `mistral-small-2603` это 0.3, у `magistral-medium`
  1.0. Зашитая в клиент константа была бы хуже для половины моделей. Поэтому
  рекомендованное значение показывается в колонке `t°`, но подставляет его сервер.
- **Параметр, которого модель не умеет, отсеивается с предупреждением.**
  `reasoning_effort` есть у `mistral-small` (`reasoning: true`), но не у
  `codestral` (`reasoning: false`). Отправить его туда — получить либо молчаливое
  игнорирование, либо 422 посреди демо:

  ```
  $ advent w01 chat "Скажи ровно: два" --model codestral-latest --reasoning-effort high
  Два.
  codestral-latest не поддерживает: reasoning_effort — параметры не отправлены
  · model codestral-latest → codestral-2508  ·  1292 ms  ·  tokens 55/4/59
  ```

- **Стрим печатается сырым текстом**, без markdown-рендера. `rich.Live` с
  перерисовкой мигает на длинных ответах, жрёт CPU и ломается при редиректе
  в файл.
- **Реальная версия модели берётся из списка моделей.** API возвращает то же
  имя, что прислали, поэтому `-latest` пришлось бы показывать как есть — а
  через месяц было бы непонятно, чем именно записано видео.
- **Принудительный UTF-8 на потоках.** Консоль Windows по умолчанию отдаёт
  cp1251, и кириллица в ответе превращается в мусор прямо в кадре.
